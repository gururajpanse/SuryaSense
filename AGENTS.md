## 1. Project in one paragraph

Semester mini project for ISRO Problem Statement 15: **forecasting and nowcasting of solar flares using combined soft X-ray (SoLEXS) and hard X-ray (HEL1OS) data from Aditya-L1**, validated against GOES-19 XRS. The pipeline detects flares as they happen (nowcast), builds a master flare catalogue, predicts the probability of a flare in the next N minutes (forecast) with a measured lead time, and shows everything in a dashboard with visual alerts.

Instruments:
- **SoLEXS**: soft X-rays. Slow rise, long decay. The "flare is happening" signal.
- **HEL1OS**: hard X-rays. Short sharp spikes, often early in the flare. Possible precursor signal.

### Objectives (from the problem statement)
1. Automated **nowcasting**: detect and classify flares in real time using soft and hard X-ray data.
2. **Forecasting**: predict flares by finding precursor patterns in both light curves.

### Expected outcomes
1. Automated database (catalogue) of nowcasted flares, from combined soft + hard light curves.
2. Trained model that forecasts flares with a quantified lead time.
3. Interface that visualises light curves and triggers visual alerts for nowcast and forecast events.

### Evaluation criteria (what we are judged on)
- Detection of both low-class (B/C) and high-class (M/X) flares.
- High true positive rate (TPR) and low false alarm rate (FAR).
- Lead time: minutes before the flare peak at which the alert fires.

## 6. Technical design

### Pipeline
```
PRADAN zips -> select light curves -> read + QC -> resample/grid (UTC)
  -> nowcast detectors (soft, hard) -> master catalogue (validated vs GOES)
  -> features + labels (chronological split) -> forecast models
  -> alert engine -> dashboard
```

### Nowcasting (no training)
- Independent detectors for SoLEXS and HEL1OS: trailing background estimate, threshold on excess, derivative/sustained-rise logic, peak finding (`scipy.signal.find_peaks`), end time as decay to background.
- Merge into a master catalogue with a source tag per event: `soft_only`, `hard_only`, `both`. Match events within a configurable time tolerance.
- Classify size (A, B, C, M, X) from the peak flux, calibrated against GOES `xrsb_flux`.
- Validate against the GOES flare summary: precision, recall, peak-time error, per-class results.
- Catalogue stored in `data/catalog/` (CSV and DuckDB or SQLite).

### Forecasting (training)
Task: probability that a flare peak occurs within the next N minutes (default **N = 30**, configurable, 60 as a stretch; owner to confirm).
- **Labels** come from the GOES-19 flare summary and 1-minute flux. GOES is ground truth for labels and scoring only, **never a model input** in the main model.
- **Features** from a trailing window (default last 60 min): current flux, trend/derivative, rolling statistics, soft-to-hard ratio, count of small bursts, time since last flare, HEL1OS band rates (when available), availability mask.
- **Model ladder** (compare each step on the same data):
  1. Threshold/persistence baseline.
  2. Logistic regression.
  3. XGBoost or LightGBM.
  4. Stretch: small 1D-CNN/LSTM; GOES pre-training then fine-tuning on Aditya-L1, compared against an Aditya-only model. Off-the-shelf time-series foundation models are optional comparison only.
- **Class imbalance**: use class weights or similar. Never report accuracy alone.
- **Probability calibration** fitted on validation only (isotonic or Platt).
- **Alert threshold** chosen on validation at a target false-alarm rate, then frozen. Test set is scored **once**.
- **Ablations**: soft only vs soft + hard (only on days with both instruments), with confidence intervals.

### Leakage controls (must be tested)
- Chronological splits only. Never random.
- 60-minute embargo between train/validation/test.
- Trailing backgrounds and filters only. No centred or two-sided smoothing that sees the future.
- Features at time t use only data up to t.
- Thresholds, calibration and model selection use validation only.

### Metrics
TPR (recall), false alarm rate (false alarms per day and false alarm ratio), precision, PR-AUC, True Skill Statistic, Brier score, calibration curve, and **lead time** (minutes between first alert and flare peak, distribution per flare class). Report separately for B/C and M/X. State sample sizes. Use bootstrap confidence intervals (resample by day) because data is small.

### Dashboard (`app/`)
- Default: Streamlit with Plotly (change only with an ADR).
- Views: SoLEXS and HEL1OS light curves (log scale), GOES overlay, detected flares from the catalogue, forecast probability line with threshold, instrument availability strip.
- **Visual alerts**: banner for nowcast (flare in progress) and forecast (probability above threshold), colour-coded by level, with the time of alert and expected class if available.
- **Replay mode**: plays back a chosen past day from precomputed predictions. The demo must work fully offline.
- Optional stretch: live GOES feed demo (`https://services.swpc.noaa.gov/json/goes/primary/xrays-1-day.json`).
- Dashboard reads precomputed files. It does not retrain or touch `data/raw`.

## 7. Coding standards

- Python 3.11+, type hints on public functions, docstrings (short, plain English).
- Format and lint: `ruff`. Types: `mypy` (strict on `src/`). Tests: `pytest` with coverage target above 70%.
- Dependencies in `pyproject.toml`, versions pinned or constrained. Core: numpy, pandas, scipy, astropy, xarray, netCDF4, scikit-learn, xgboost or lightgbm, plotly, streamlit, pyarrow, duckdb, pyyaml, pytest, ruff, mypy.
- No hard-coded paths, dates or thresholds. Use `config/`.
- Pure functions where possible. Separate I/O from logic.
- Use `logging`, not `print`, in library code.
- Reproducibility: fixed random seeds, config saved with every run, outputs written to `data/processed/`, `models/`, `reports/`.
- Small commits, clear messages. Do not commit unless asked.
- Refactor after each module works: remove duplication, improve names, add tests.

## 8. Testing requirements

- **Unit tests**: readers, QC masks, detectors, label builder, feature windows.
- **Synthetic tests**: fake flare shapes (fast rise, slow decay) must be detected; flat noise must not.
- **Leakage tests**: perturb future values and assert earlier features do not change; assert splits do not overlap and respect the embargo.
- **Data tests**: monotonic UTC timestamps, no silent NaN fill, duplicate-day detection.
- **Model tests**: shapes, probabilities in [0, 1], reproducible with a fixed seed.
- Tests use small fixtures in `tests/fixtures/`. They must not need real data or network.

## 9. CI/CD and DevOps

- GitHub Actions on every push and pull request: ruff, mypy, pytest with coverage. CPU only, no data.
- Dockerfile for the dashboard using sample/precomputed outputs only.
- Makefile targets mirror CI steps.
- Optional deployment of the dashboard with sample data only.

## 10. Security rules

- PRADAN credentials may appear in downloaded helper scripts. Keep those scripts out of git.
